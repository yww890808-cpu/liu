# 首次接入真实店铺检查清单

按顺序进行，每一步确认无误再做下一步。**完成第 5 步之前，`.env` 中保持 `DRY_RUN=true`。**

## 1. 添加店铺并测试连接
- [ ] Ozon 卖家后台 → 设置 → API 密钥，生成一个 Api-Key（建议单独为本系统生成，便于以后作废）
- [ ] 管理后台“店铺”页添加店铺，填写 Client-Id 和 Api-Key
- [ ] 点“测试连接”，提示“连接成功，共 N 个仓库”，N 与 Ozon 后台 FBS 仓库数一致

## 2. 同步商品与仓库
- [ ] 点“同步商品”，约 1 分钟后到“日志 → 任务记录”，看到“同步商品/仓库：成功”
- [ ] 展开店铺，仓库列表与 Ozon 后台一致
- [ ] “库存”页能看到全部在售商品，货号、名称正确

## 3. 核对库存初始值（重要）
同步商品时会自动读取 Ozon 当前库存作为本地初始值。
- [ ] 抽查 3–5 个商品：“库存”页每个仓库的数字 = Ozon 后台该仓库的**可售数量**（总数减去已预留）
- [ ] 对不上时**不要关闭试运行**，把差异截图反馈

## 4. 订单
- [ ] 店铺页点“拉取订单”，或等待最多 10 分钟自动拉取
- [ ] “订单”页能看到待备货订单，商品、数量、仓库、最晚发货时间与 Ozon 后台一致

## 5. 试运行检查写操作
- [ ] 选一笔待备货订单点“备货”，弹出“试运行”窗口，核对将提交的货件号、商品和数量
- [ ] 库存页改一个商品的数量 → 保存修改 → 立即推送；到“日志 → 任务记录”看“推送库存（试运行）”中的内容：货号、仓库、数量正确

## 6. 关闭试运行，小范围验证
- [ ] `.env` 中改为 `DRY_RUN=false`，执行 `docker compose up -d`，后台顶部的黄色试运行提示消失
- [ ] **只对 1 笔订单**备货 → 约 1 分钟后下载面单 PDF → 在 Ozon 后台确认该订单已变为“待发运”，物流单号一致
- [ ] **只改 1 个商品 1 个仓库的库存** → 立即推送 → 日志显示成功 → Ozon 后台该商品库存已变化
- [ ] 观察一天：日志页“只看失败”没有持续出现的错误

全部通过后即可正常使用。任何一步出现问题，把“日志”页的错误信息（或截图）发给开发者。

## 需要用真实店铺确认的几点
开发时无法访问 Ozon 官方文档，以下内容根据开源客户端源码实现，请在上面的步骤中留意：
1. 订单拉取同时使用“创建时间（最近 90 天）”和“状态变更时间（最近 3 天）”两个条件（第 4 步）
2. 库存可售数 = Ozon 返回的总数 − 预留数（第 3 步）
3. 面单未生成时，按错误信息中的 “not ready” 判断并自动重试（第 6 步）
